# Recording jobs, deletion and storage

## Scope and ownership

Integration task based on feat/m2 at 35f6b37, implementing ADR-0005 sections
4-6 and deployment design sections 6.4 and 8. Persistence, Media, API/Auth,
Shared Types, Teacher and QA changes belong to this one draft PR. No cloud
resources, deployment, Admin UI, domains or performance tuning are included.

## Contracts

- POST /recording/{id}/process: OP or teacher review, strict revocation.
  Only complete takes; 202 `{session_id,status:"queued",job_id}`.
  allow_missing_header remains OP-only and never bypasses completeness.
- GET /sessions/{id}/recording: existing review read permissions plus OP.
  200 `{session_id,url,expires_in:900,recording_state}` for a verified MP4;
  otherwise 202 with the queued job, 404 for no take, 409 for incomplete.
  No request runs FFmpeg. Recording GET/status return 410 for tombstones.
- DELETE /sessions/{id}/recording: teacher review or OP, strict grant/token
  revocation, JSON `{confirm:session_id}`; idempotent 202
  `{session_id,recording_state:"deleting"|"deleted"}`. Upload/finalize/process
  refuse tombstones. Events, timeline, audit and review grants are retained.
- Local storage returns a 15-minute HMAC-signed /recording-media/{id} URL;
  this capability serves only that MP4 and rechecks its tombstone. S3/R2 uses
  the SDK presigned GET. API bearer/grant tokens never enter media URLs.

## Invariants and acceptance

Atomic SQLite UPDATE RETURNING claims, active-kind/session deduplication,
one execution worker and lease-only heartbeats during blocking IO; startup
recovers previous instance jobs, five-minute stale leases are checked every
minute. Ordinary jobs have three attempts; deletion jobs retry indefinitely.
No DB write transaction crosses FFmpeg, storage or filesystem cleanup.
Recheck cancellation before stages and after upload. Late uploads enqueue
durable orphan deletion. Startup/hourly reconciliation revisits fixed keys
even after recording_key was cleared. Additive migration preserves old rows.
Only keys/checksums/manifests are persisted, never signed URLs. Verified MP4
precedes raw cleanup; incomplete/failed takes retain originals; MP4 stays local.

Acceptance: Windows backend suite including real FFmpeg; concurrent claim,
restart/heartbeat/retry tests; delete auth/confirm/idempotency/410; cancellation
during upload, retrying deletion and restart orphan reconciliation; signed
local expiry/range/path binding; fake-client S3 tests; backup restore and raw
retention tests. Run affected Teacher/shared tests and production builds.
Real R2 and cloud/browser deployment acceptance remain separate.

## Local operation and configuration

Use one uvicorn process (`--workers 1`) and one execution worker. Do not run a
second backend against the same SQLite file: startup lease recovery assumes
the previous process has exited. SQLite must support UPDATE RETURNING (3.35+).
Persist the database, sessions directory and local objects directory together.
The additive migration adds five nullable recording columns and the jobs
table/index; it does not modify or delete existing session/media rows.

| Setting | Default / purpose |
| --- | --- |
| MINDPROBE_JOB_WORKER | true; false disables execution for tests/maintenance |
| MINDPROBE_STORAGE_BACKEND | local; s3 selects the S3-compatible adapter |
| MINDPROBE_LOCAL_STORAGE_DIR | ./objects, private, never mount this whole directory publicly |
| MINDPROBE_S3_ENDPOINT / MINDPROBE_S3_REGION | S3-compatible endpoint and region (R2: auto) |
| MINDPROBE_S3_ACCESS_KEY_ID / MINDPROBE_S3_SECRET_ACCESS_KEY | Inject credentials only for an explicitly configured remote backend |
| MINDPROBE_RECORDINGS_BUCKET | Private recording and backup bucket; required for s3 |
| MINDPROBE_WS_TOKEN_SECRET | Existing persistent signing secret; also domain-separates local media signatures |
| MINDPROBE_UPLOAD_GRACE_SECONDS | Existing grace duration, default 600; not extended by jobs |
| MINDPROBE_UPLOAD_GRACE_SYNTHESIZE_AFTER | Existing historical-session cutover policy, unchanged |

The former minute grace thread is replaced by durable finalize_timeout jobs;
MINDPROBE_UPLOAD_GRACE_SCHEDULER is no longer the execution switch. Worker
maintenance scans each minute, records daily UTC backups under
`backups/sqlite/YYYY-MM-DD/mindprobe.db.gz`, and reconciles deletions hourly.
The compressed backup is made using SQLite's online backup API, not a live
database file copy. Retention/lifecycle and off-machine restore drills still
need deployment configuration. Local archived copies remain private.

Ordinary failed jobs retry with 60/300/900-second bounded backoff and a
three-attempt limit. An operator can explicitly enqueue processing again
after addressing the cause. GET polling returns processing_failed after an
exhausted job instead of silently starting a fresh retry budget.
Deletion jobs have no attempt limit. Inspect
jobs.status, attempts, heartbeat_at and last_error together with recording
state; no management UI is included. Logs name the job/error class rather
than recording URLs or credentials.

After completion, browser receipt reconciliation uses the persisted manifest
even when raw chunks have been cleaned up. A matching late duplicate is
acknowledged without recreating raw files; conflicting bytes remain rejected.
Incomplete media cannot be rescued by a processing request in this batch.
Explicit authorized DELETE removes the take's media even if it is incomplete;
events, audit and grant records survive. Already-issued remote signed URLs
may remain usable until expiry/cache eviction; infrastructure snapshots keep
their copies until their own retention expires. Include this in privacy notices.

## Review boundaries

Backend/library and worker tests are automated. Teacher changes include
direct signed-URL playback, renewal on media error with position restoration,
a teacher-review-only confirmation control, and polling deletion to completion.
Manual camera/Teacher/Safari acceptance is for the independent QA round.
No real R2 request, cloud bucket, Lightsail, Caddy or Vercel configuration was
used for these tests. S3 behavior is tested through an injected fake client.

Primary references: [SQLite partial indexes in SQLAlchemy](https://docs.sqlalchemy.org/en/20/dialects/sqlite.html#partial-indexes)
for active-job uniqueness and [Boto3 presigned URLs](https://docs.aws.amazon.com/boto3/latest/guide/s3-presigned-urls.html)
for private object delivery. The project's authorization/retention policy is
defined by [ADR-0005](adr/0005-cloud-deployment-and-recording-retention.md).
